# 🇯🇵 日本雙城刷卡決策與記帳助手

專為赴日旅遊設計的信用卡決策、額度監控、即時記帳與**多裝置雲端同步** Web App。

---

## 📱 核心特色

1. **☁️ 旅程房間碼（跨手機多裝置雙向同步）**
   - **自訂/隨機代碼**：點擊右上角「☁️ 本地」即可輸入代碼（如 `TOKYO2026`）或隨機產生代碼（如 `JP-8921`）。
   - **多裝置/旅伴共享**：使用 Supabase `japan_card_data` 資料表；同一房間的裝置同步卡片規則、剩餘額度、週期狀態與記帳明細。
   - **一鍵專屬分享網址**：網址會帶上房間代碼，旅伴點開即可載入同一房間。
   - **斷網離線保護**：日本地下鐵或地下美食街訊號不好時，優先儲存於手機本地快取，有網路時自動連線同步。

### Supabase 資料表權限

前端使用 publishable key 呼叫 Supabase REST API。若新專案尚未授予 Data API 權限，請在 SQL Editor 執行：

```sql
grant select, insert, update on table public.japan_card_data to anon;
```

目前的 `Allow public read and write` RLS policy 允許匿名使用者讀寫所有房間列。房間代碼只是識別碼，不是存取控制；不要在同步資料放敏感資訊。Supabase publishable key 會公開在網頁程式中，不能當作密碼。

### 臺銀日圓匯率（首次設定一次）

瀏覽器無法直接讀取臺銀頁面，因此需要在現有 Supabase 專案建立一個轉接函式。**不用安裝 CLI，也不用改資料庫**：

1. 開啟 [Supabase 專案](https://supabase.com/dashboard/project/bcxjbeiqunohwpvxzyaf/functions)，進入 **Edge Functions**。
2. 按 **Deploy a new function → Via Editor**，函式名稱填 `bot-jpy-rate`。
3. 將本資料夾 `supabase/functions/bot-jpy-rate/index.ts` 的內容貼入編輯器，再按 **Deploy function**。
4. 回到 App 點「更新臺銀匯率」確認成功。之後 App 會在頁面開啟時及每 15 分鐘自動檢查；以臺銀頁面實際牌價時間為準，非營業時間可能維持原價。

匯率讀取失敗或無法確認臺銀牌價時間時，App 會保留舊值並標示更新失敗，不會把舊資料冒充新報價。臺銀牌價僅供參考，實際交易價格以發卡銀行或臺銀交易畫面為準。

2. **⚡ 櫃檯速查決策器**
   - **依情境推薦卡片**：交通卡、熊本熊指定店、富邦 J 卡、Costco、PayPay 與 CUBE 依規則計算淨回饋與門檻。
    - **PayPay 掃碼支援**：玉山 Wallet 綁熊本熊淨回饋 3.5%，達上限後可切換扣外幣帳戶。
   - **致命陷阱防呆**：
       - 自動警示**百貨商場統收機台**（熊本熊指定店 6% 加碼不適用）。
       - 富邦 J 卡一般消費單筆滿 NT$1,000、交通卡儲值單筆滿 NT$2,000 才符合加碼門檻；未達時會改推符合條件的卡片。
   - **先選消費情境**：一般消費／特約商店／PayPay／交通卡四個情境卡；選「特約商店」時再從維護的店家清單挑選（松本清、BicCamera、唐吉訶德等）。
   - **金額快捷鍵**：支援快速加點 `+1,000`、`+5,000`、`+10,000`、`+30,000`。
   - **拆刷記帳**：超過加碼額度時顯示每張卡的刷卡金額；實際拆刷後可選方案逐筆記帳，分別扣除各卡額度。

3. **💳 加碼額度與週期看板**
   - 視覺化進度條（充足綠色 ➔ 警示橙色 ➔ 告急紅色）。
   - 雙幣顯示：同時呈現台幣剩餘額度與換算後的日幣參考額度。
   - 每筆額度都標示「卡片 · 方案 · 項目」、門檻、週期與下次重置日；上限、已用與剩餘直接由 `rulesV3` 的回饋項目欄位算出，不是另存一份額度表。
   - 季、月、帳單週期在頁面開啟、恢復與每分鐘檢查時自動歸零重算；首次使用會詢問玉山卡每月結帳日，熊本熊與 PayPay 共用該日期。未知時不猜日期並維持手動重置。
   - 可對單一項目重置或一鍵全部重置，重置後會回寫同一份 `rulesV3` 並同步到房間。
   - 攻略守則頁的「編輯」入口（單卡編輯頁）與「新增信用卡」畫面是卡片回饋規則的編輯入口；額度上限與刷卡推薦都由同一份規則推導。

4. **📖 攻略守則（閱讀優先，兩種檢閱模式）**
   - **卡片 / 表格切換**：右上角一鍵切換檢閱模式，兩者讀同一份 `rulesV3` 資料，與刷卡決策頁的試算結果一致；模式會記在瀏覽器，下次開啟沿用。
   - **卡片模式**：一張實體卡一張卡，加碼方案預設收合；每個方案只顯示一個適用情境，點開後用與表格相同的欄位呈現一般回饋、加碼、手續費、淨回饋、門檻、計算週期、額度上限，以及活動期間與登錄提醒；持有中與未持有的卡片分區顯示。
   - **表格模式**：九欄橫向比對（信用卡／情境／一般回饋／加碼／手續費／淨回饋／門檻／計算週期／額度上限），手機上在表格內左右滑動即可。
   - **每張卡片都有「編輯」按鈕**：卡片模式每張卡右上角、表格模式每張卡的第一列都有「編輯」；點擊後開啟**這一張卡專屬的獨立編輯頁**，不用回到全部卡片的清單裡找。
   - **單卡編輯頁**：頁面上半是這一張卡的基本設定（名稱／發卡銀行／卡片組織／一般回饋率／收海外手續費／是否持有），下半是這一張卡自己的加碼活動（可新增、編輯、刪除），最下方是危險區「刪除這張卡」。所有修改即時寫回同一份 `rulesV3`。
   - **單卡編輯頁兩層結構**：上半是這一張卡的基本設定，下半是這一張卡自己的加碼活動清單；點「＋ 新增加碼活動」才展開加碼活動表單，名稱、情境、門檻、上限、期間都在表單裡維護。加碼活動表單直接掛在這張卡的下方，不另設一個孤立的「新增方案」區塊。
   - **「新增信用卡」是整頁、不是彈窗**：攻略頁右上角的按鈕開啟後是一整頁（沒有彈窗視窗、沒有卡片清單、也沒有搜尋框）。右上角有「✕」叉叉可關閉；最下方是固定的「新增信用卡」鈕。
   - **新增頁會取代底部 tab 列**：新增頁開啟時底部導覽列整個隱藏，由最下方的固定「新增信用卡」鈕取代，使用者不會一不小心就跳出編輯畫面；要離開只能用右上角的叉叉（Esc 也可以）。
   - **欄位垂直排列、不要框中框**：標題下直接列出欄位，單欄往下排列（卡片名稱／一般回饋率／收海外手續費），不再用並排的兩欄格，也沒有外框再套外框。
   - **新增信用卡只收必要欄位**：卡片名稱／一般回饋率／是否收海外手續費。卡片組織（Visa、Mastercard…）與發卡銀行不影響試算，所以新增時不填，之後可在該卡的編輯頁補填。
   - **新增完直接進那張卡**：在「新增信用卡」頁送出後，會自動關閉並直接開啟那張新卡的單卡編輯頁，馬上就能替它加碼活動。
   - **加碼活動的適用情境用分段按鈕**：一般消費／交通卡／特約商店／PayPay 四選一；選「特約商店」才會出現適用店家清單，並可在同一處直接新增店家。
   - **所有勾選框都改成手機開關**：像是「收海外手續費 1.5%」、「我持有這張卡」、「與一般回饋併計」、「需手動登錄或切換權益」、「與第一項共用額度」都不再用方框勾選，改成可以左右滑動的開關（開＝青色滑到底，關＝灰色滑到左邊）。
   - **所有頁面寬度一致、置中**：主頁（決策／額度／記帳／攻略）、單卡編輯頁與「新增信用卡」整頁共用同一個內容寬度（桌機 1040px，手機＝視窗扣掉左右留白），左右邊界完全對齊，不會出現「編輯頁突然變很寬」或「表單貼在左邊」的情況。
   - **標題在文字框的左上方**：每個欄位的標題都排在輸入框正上方且靠左對齊（不再置中），一眼看得到這格是什麼、要去哪裡填。
   - **回饋率輸入框有 ＋/－ 步進鈕**：回饋率、門檻、上限等數字欄位左右各有一顆 48px 的 ＋/－ 按鈕，手機上不用開小鍵盤、不用瞄原生上下箭頭，直接點就加減（會遵守 `min`／`max`／`step`，並即時回寫規則）。
   - **手機優先**：輸入框不會被底部固定按鈕或彈出的螢幕鍵盤蓋住——表單容器預留底部空間、輸入框聚焦時自動捲進可視範圍、鍵盤彈出時整頁高度跟著縮（底部「新增信用卡」鈕永遠保持在鍵盤上方）。
   - **同一種元件，長得一樣**：全站的尺寸、字級、間距與主色都來自 `:root` 的一組 design token（原本散落各處的 27 種硬編碼主色已收斂成 13 階階梯）；欄位、開關、步進鈕、按鈕、區塊容器各自只有**一份**規格，所以「新增信用卡頁」、「單卡編輯頁」、「加碼活動表單」裡的同款元件完全一致（原本同一個欄位標籤有 3 種字級／間距寫法，已合併）。
   - 刪除卡片或加碼活動前會二次確認，已有消費紀錄者則擋下避免帳本不一致。
   - **單一真相**：卡片規則、加碼額度、門檻提示、週期重置與雲端同步全部只讀同一份 `rulesV3` 資料，沒有第二份平行設定；新增一張卡時，所有頁面立刻套用同一組通用規則（一般回饋率、海外手續費、門檻、上限、週期都從同一筆資料推導）。

5. **📝 旅日消費明細與統計**
   - 完整記帳歷史，記錄消費時間、項目、日幣、台幣、預估回饋金。
   - **誤記 / 退稅還原機制**：刪除紀錄會自動將額度加回對應卡片。
   - 支援一鍵將資料匯出為 JSON 備份檔。
   - 修改規則時會保留本期已用額度，之後的消費直接套用新規則；已記錄的消費明細保留當時的規則快照，不會被回溯改寫。

6. **💴 臺銀匯率隨手調**
   - 預設讀取臺銀日圓即期賣出牌價；點擊右上角匯率標籤可手動更新或自訂。

7. **🎨 區塊層級看得清楚**
   - 每個卡片、攻略卡、編輯區塊、額度項目與記帳列都有一圈**淺色細外框**，區塊邊界一眼分得清，不會糊成一片。
   - 有語意的框維持自己的配色：推薦結果與彈窗用霓虹青、危險操作（刪除）用紅框、額度告警用桃紅框。

## 🧱 設計系統：Token、元件與契約測試

`index.html` 是單一檔案的靜態 App（沒有 npm、沒有建置步驟，拖資料夾就能上線）。為了在這種前提下仍然避免「每個頁面各做各的」，專案自製了一套輕量 design system，三層：

**1. Token 層（唯一來源）**

`:root` 裡定義了全站要用的尺寸、字級、間距與主色階梯：

| 類別 | Token |
|---|---|
| 版面 | `--page-width`（1040px）、`--page-gutter`（左右留白） |
| 尺寸 | `--control-h`（46px）、`--tap-min`（44px）、`--stepper-w`（48px）、`--field-gap`（8px）、`--btn-h` / `--btn-sm-h`、`--toggle-w` / `--toggle-h` / `--toggle-knob` / `--toggle-travel` |
| 字級 | `--fs-page-title` ＞ `--fs-title` ＞ `--fs-form-title` ＞ `--fs-label` ＞ `--fs-small` |
| 主色階梯 | `--a03` … `--a70`（13 階） |

> **規則：除了 token 定義本身，CSS 不得再出現硬編碼的 `rgba(0,240,255,…)`。** 要改主色，改 token 就好，不用逐處找。

**2. 元件層（每種元件只定義一次）**

欄位 `.field`、開關 `.toggle`、步進鈕 `.stepper`、按鈕 `.btn-small` / `.btn-main`、區塊容器 `.editor-section` 等，樣式都只有一份並被所有頁面共用。新增表單欄位只要掛 `class="field"` 就自動符合規格。

**3. 契約測試層（防止再次漂移）**

`tests/dscontract.html` 會走訪所有畫面，斷言：

- `:root` 之外沒有硬編碼主色；
- 欄位標籤／輸入框／下拉／步進鈕／開關軌道／開關文字／小按鈕／區塊容器，跨頁面的 computed style 簽章**各自唯一**；
- 各元件實際尺寸等於對應 token；
- 字級階梯遞減且各級唯一；
- 沒有裸露的勾選框、表單內數字欄位都有 ＋/－ 步進鈕、欄位規格只有一條 CSS 規則。

**新增元件時怎麼做才不會又長歪**

1. 尺寸、字級、間距一律引用上表的 token，不要寫死數值。
2. 樣式寫成 `.xxx` 一次，頁面只掛 class；不要在頁面專屬選擇器裡再覆寫字級或間距。
3. 跑一次 `./tests/run.sh`（含 `dscontract`），如果它報「不一致」，代表新元件還沒接上規格。

> 這層是**自製**的，不是引入外部 UI Library —— 因為這個 App 必須維持「零建置、零依賴、拖資料夾就上線」，而一致性要靠 token 與契約測試，不靠框架。
>
> 測試怎麼跑見 [`tests/README.md`](tests/README.md)。

## 🚀 30 秒免費部署上線（不用帶資料夾出國）

### 🏆 方式一：Netlify Drop（最簡單！純滑鼠拖曳，30 秒完成）
1. 電腦瀏覽器打開：[https://app.netlify.com/drop](https://app.netlify.com/drop)
2. 將桌面的 **`japan cards`** 資料夾直接**拖曳進網頁**。
3. 系統會在 10 秒內自動產生一組專屬 HTTPS 網址（例如 `https://japan-cards-chen.netlify.app`）。
4. 手機打開該網址，點 Safari「分享」➔ **「加入主畫面」**，立即變成獨立 App！

### 方式二：GitHub Pages（永久保存、自訂專案）
1. 在 GitHub 建立一個公開儲存庫（Repository，例如 `japan-cards`）。
2. 將此資料夾內的檔案上傳至該儲存庫。
3. 進入儲存庫的 **Settings ➔ Pages**，Source 選擇 `Deploy from a branch`，Branch 選擇 `main` 儲存。
4. 即可獲得永久網址：`https://<你的GitHub帳號>.github.io/japan-cards/`。
